# Plan: car-wash-checker

> 세차 가능 여부를 날씨·대기질·기온/습도를 종합해 판단해 주는 정적 웹 앱

- **Feature ID**: car-wash-checker
- **Level**: Starter (정적 웹, HTML/CSS/JS)
- **PDCA Phase**: Plan
- **Created**: 2026-05-02
- **Owner**: aijunny0604

## 1. 배경 (Why)

세차 후 비/눈/황사가 와서 차가 더러워지면 시간과 비용이 낭비된다.
일기예보 앱은 많지만 "지금 세차해도 되는지"를 한눈에 판단해 주는 도구는 드물다.
사용자는 단순 강수확률뿐 아니라 **미세먼지/황사**, **기온/습도(건조 속도, 결빙 가능성)**까지 함께 보고 결정하고 싶어한다.

## 2. 목표 (Goal)

- 사용자의 **현재 위치**(GPS 자동)에서 **앞으로 7일** 동안의 날씨/대기질을 종합해
  "세차 OK / 보류 / 비추천" 신호를 명확히 보여준다.
- 무료 API **여러 개를 병렬로 호출**해 한 곳이 막히거나 누락돼도 폴백으로 작동.
- 백엔드 없이 **순수 정적 웹**으로 배포 (GitHub Pages / Vercel Static).

## 3. 비목표 (Non-goals)

- 회원가입·로그인·DB·푸시 알림 (MVP에서 제외, v2 고려)
- 결제, 세차장 예약 연동
- iOS/Android 네이티브 앱 (PWA 설치는 후속 단계 옵션)

## 4. 사용자 시나리오

1. **앱 첫 진입** → "위치 권한 허용?" 묻기 → GPS로 좌표 획득
2. 좌표 기반으로 **3개 이상 API 병렬 호출** (날씨 2종 + 대기질 1~2종)
3. **오늘** 카드 큰 신호등(🟢/🟡/🔴) + 한 줄 사유 ("내일 비 80% — 보류")
4. **7일 타임라인**: 날짜별 세차 점수 + 강수/미세먼지/온습도 요약
5. 권한 거부 시 **도시 수동 선택** 폴백 (서울/부산/…)

## 5. 판단 로직 (Decision Rules)

각 일자에 대해 0~100점 산출 후 등급화:

| 항목 | 가중치 | 감점 규칙 (예시) |
|------|--------|------------------|
| 강수확률 (오늘 + 익일) | 40 | 익일 강수확률 70%↑ → -40 |
| 미세먼지/황사 (PM10, PM2.5) | 25 | PM10 ≥ 150 또는 황사 경보 → -25 |
| 기온 (결빙) | 15 | 야간 최저 ≤ -2℃ → -15 (결빙 우려) |
| 습도 / 건조 시간 | 10 | 습도 ≥ 85% 종일 → -10 |
| 풍속 (먼지 재부착) | 10 | 풍속 ≥ 8m/s → -10 |

**등급**:
- 🟢 OK: 80 ↑
- 🟡 보류: 50 ~ 79
- 🔴 비추천: 49 ↓

## 6. 데이터 소스 (무료 API 다중 종합)

> **핵심 원칙**: 한 곳에 의존하지 않고 **날씨 6종 + 대기질 4종**을 모두 병렬 호출해 합의(consensus)로 결정.
> 그중 **4종은 API 키 없이 즉시 동작**해서 키 미설정 환경에서도 기본 기능 보장.

### 6.1 날씨 소스 (6종)

| # | API | 키 | 무료 한도 | 신뢰 가중치 | 비고 |
|---|-----|----|-----------|--------------|------|
| 1 | **Open-Meteo** | ❌ | 무제한(비상업) | 1.0 | 시간별 7일+, ECMWF/GFS 앙상블 |
| 2 | **MET Norway (Yr.no)** | ❌ | UA만 필요 | 1.0 | 노르웨이 기상청, 글로벌 정확도 |
| 3 | **기상청 단기예보** | ✅ | 일 10,000 | 1.2 (한국 한정) | 한국 격자 강수확률 |
| 4 | **OpenWeather One Call 3.0** | ✅ | 일 1,000 | 0.9 | 7일 일별 |
| 5 | **Weatherbit** | ✅ | 일 50 | 0.8 | 보조 교차검증 |
| 6 | **7Timer!** | ❌ | 무제한 | 0.7 | 단순 JSON, 폴백 |

### 6.2 대기질 소스 (4종)

| # | API | 키 | 무료 한도 | 신뢰 가중치 | 비고 |
|---|-----|----|-----------|--------------|------|
| 1 | **에어코리아 (data.go.kr)** | ✅ | 일 10,000 | 1.5 (한국 한정) | 한국 PM10/PM2.5/황사 공식 |
| 2 | **Open-Meteo Air Quality** | ❌ | 무제한 | 1.0 | PM10/PM2.5 글로벌, CAMS 기반 |
| 3 | **WAQI (aqicn.org)** | ✅ | 1,000 req/sec | 0.9 | 글로벌 AQI |
| 4 | **IQAir AirVisual** | ✅ | 일 10,000 | 0.9 | 글로벌 보조 |

### 6.3 종합 전략

- **모든 fetch는 `Promise.allSettled`로 동시 호출**, 실패는 조용히 제외
- **가중 평균 + 이상치 제거(IQR 또는 ±1.5σ)** 후 합의값 산출
- **강수확률**: 가중 평균 후 max도 함께 표시 (보수적 알림용)
- **PM10/PM2.5**: 한국 좌표면 에어코리아 가중치 1.5 → 다른 소스 평균과 가중합
- **황사 경보**: 어떤 소스든 true면 true (OR 결합, 안전 우선)
- **최소 가용 소스**: 날씨 1종 + 대기질 0종이면 동작 (대기질 무시 점수). 모두 실패하면 ErrorState
- **UI 배지**: "데이터 N/10 종합" + 출처 목록 (예: "Open-Meteo · MET · 에어코리아 · WAQI")
- **사용자 제어**: 설정에서 개별 소스 ON/OFF 가능

## 8. 기술 스택

- **Frontend**: HTML5 / CSS3 (Grid, CSS variables) / Vanilla JS (ES2022 모듈)
- **API 호출**: `fetch` + `Promise.allSettled`
- **위치**: `navigator.geolocation`
- **폴백 도시**: 정적 JSON (서울/부산/대구/인천/광주/대전/울산/세종 + 위도경도)
- **빌드**: 없음 (정적), 또는 Vite로 단순 dev 서버
- **배포**: GitHub Pages 또는 Vercel Static

## 10. 위험 / 가정

- **API 키 노출 위험**: 정적 웹이라 키가 클라이언트에 노출됨 → **키 필요 API는 도메인 제한·rate limit 의존**, 또는 v2에서 Cloudflare Worker 프록시 도입
- **CORS**: Open-Meteo·OWM·WAQI는 CORS 허용. 에어코리아는 일부 엔드포인트 CORS 비허용 가능 → 우선순위 후순위로 두고 WAQI 폴백 보장
- **GPS 거부**: 도시 수동 선택 폴백 필수
- **무료 한도 초과**: 사용량 적은 개인 도구 가정, 초과 시 Open-Meteo만으로도 동작하도록 graceful degradation
